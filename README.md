# ProjectGlue 🧩

> **Zero-dependency Codebase Bundler for AI Analysis (LLM Context Preparer)**  
> Утилита для автоматической сборки проектов на любых языках (**Java, Python, TypeScript, Go, C#, Rust, C++** и др.) в структурированные текстовые тома для скармливания нейросетям (**Gemini, Claude, GPT-4o, DeepSeek**).

---

## 🎯 Зачем это нужно?

Современные языковые модели поддерживают огромные контекстные окна (от 128K до 2M токенов). Загрузив проект целиком, вы можете мгновенно получить:
- Глубокий аудит архитектуры и поиск межмодульных ошибок;
- Быстрый онбординг в незнакомый репозиторий («где что копать и как это работает»);
- Комплексный рефакторинг и написание тестов с учетом зависимостей между классами.

**ProjectGlue** решает главные проблемы ручной подготовки кода:
1. ✂️ **Неделимость файлов (Atomic File Mode)**: файлы исходного кода **никогда не разрываются** между томами. Классы и функции всегда попадают в бандл целиком.
2. 📦 **Разбиение на тома по ~0.5 МБ (или любой лимит)**: бандл делится на удобные части `_part1.txt`, `_part2.txt`, идеально проходящие через лимиты загрузки в веб-интерфейсах нейросетей.
3. 🗺️ **Полная карта репозитория в каждом томе**: каждый файл-том содержит единое ASCII-дерево каталогов **всего** проекта и собственное оглавление (TOC). Даже изучая отдельный том, модель видит архитектуру целиком.
4. 🛡️ **Умная фильтрация**: автоматически отсекает бинарники (`.jar`, `.class`, `.pyc`, `.exe`), медиафайлы, зависимости (`node_modules`, `venv`, `target`, `build`), гигантские lock-файлы (`package-lock.json`, `poetry.lock`) и секреты (`.env`, `*.pem`, `*.key`).
5. ⚡ **Zero Dependencies**: не требует установки Python, Node.js или сторонних пакетов. Работает «из коробки» на чистой Windows и любых дистрибутивах Linux / macOS.

## 🚀 Быстрый старт

В репозитории два скрипта с полностью идентичной логикой:
- `bundle.bat` — для Windows (работает по двойному клику или из CMD);
- `bundle.sh` — для Linux, macOS и WSL.

### Запуск на Windows

1. Скопируйте `bundle.bat` в корень проекта.
2. **Просто дважды кликните по нему** в Проводнике Windows  
   *или запустите из командной строки:*
   ```cmd
   bundle.bat
   ```
3. Рядом появятся готовые файлы томов:
   ```
   [ProjectName]_part1.txt
   [ProjectName]_part2.txt
   ...
   ```

**Дополнительные параметры (Windows):**
```cmd
bundle.bat "C:\Path\To\Project"        :: Собрать проект по указанному пути (лимит 500 КБ)
bundle.bat . 1000                      :: Собрать текущий проект с томами до 1000 КБ (1 МБ)
bundle.bat "C:\MyProject" 250          :: Указать и путь, и лимит в КБ
```

---

### Запуск на Linux / macOS / WSL

1. Скопируйте `bundle.sh` в корень проекта.
2. Сделайте исполняемым (один раз) и запустите:
   ```bash
   chmod +x bundle.sh
   ./bundle.sh
   ```

**Дополнительные параметры (Linux):**
```bash
./bundle.sh /path/to/project           # Собрать проект по указанному пути (лимит 500 КБ)
./bundle.sh . 1000                     # Собрать текущий проект с томами до 1000 КБ (1 МБ)
./bundle.sh /path/to/project 250       # Указать и путь, и лимит в КБ
```

## 📋 Формат выходных томов

Каждый том размечается метаданными, структурой и XML-тегами:

```xml
================================================================================
CODEBASE BUNDLE FOR AI ANALYSIS
Project:     MyApplication
Volume:      Part 1 of 2
Date:        2026-10-30 22:00:00
Files Here:  14 in this volume (Total project files: 25)
Max Limit:   500 KB per volume (Atomic file mode: files are never split)
================================================================================

================================================================================
1. FULL PROJECT DIRECTORY STRUCTURE
================================================================================
MyApplication/
|-- pom.xml
|-- README.md
+-- src/
    +-- main/
        +-- java/
            +-- com/
                +-- example/
                    |-- Application.java
                    +-- service/
                        +-- UserService.java

================================================================================
2. FILES IN THIS VOLUME (Part 1 of 2)
================================================================================
  1. pom.xml (2.45 KB)
  2. README.md (1.20 KB)
  3. src/main/java/com/example/Application.java (1.80 KB)
  ...

================================================================================
3. SOURCE CODE FILES
================================================================================

================================================================================
FILE [1/14 in Part 1 | Overall 1/25]: pom.xml
LANGUAGE: xml | SIZE: 2.45 KB
================================================================================
<file path="pom.xml">
... исходный код файла без искажений ...
</file>

================================================================================
FILE [2/14 in Part 1 | Overall 2/25]: README.md
LANGUAGE: markdown | SIZE: 1.20 KB
================================================================================
<file path="README.md">
... исходный код файла ...
</file>
```

## ⚙️ Пользовательские исключения (`.bundleignore`)

Если вам нужно исключить специфичные файлы или папки проекта (дампы базы данных, моки, фикстуры, устаревший код):
1. Создайте в корне проекта файл `.bundleignore` (см. пример [.bundleignore.example](.bundleignore.example)).
2. Добавьте пути или маски:
   ```gitignore
   # Исключить папку
   fixtures/
   mock_data/

   # Исключить по маске
   *.sql
   *.csv
   legacy_*
   ```

## 🤖 Готовый промпт для отправки в нейросеть

Прикрепите созданные файлы (`[Project]_part1.txt`, `[Project]_part2.txt`, ...) к диалогу с нейросетью и отправьте следующий промпт:

> **Промпт для нейросети:**  
> «Я прикрепил полный срез кодовой базы проекта, разделенный на тома до 0.5 МБ. В начале каждого тома приведено полное дерево каталогов репозитория, оглавление текущей части, а далее — файлы с исходным кодом в тегах `<file path="...">`.  
> 1. Изучи проект целиком и опиши его стек, назначение и общую архитектуру.  
> 2. Укажи главные точки входа (entry points) и потоки данных.  
> 3. Подскажи, где что искать при доработке и какие архитектурные узкие места или потенциальные баги ты видишь.»
